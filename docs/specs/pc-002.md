# PC-002 — Migrations, Offers and Product Lifecycle

Status: PLANNED
Depends on: PC-001

## Objective

Introduce versioned database migrations and extend
the Product Core to manage commercial offers
and product lifecycle transitions.

## Deliverables

### Database Migrations
- Alembic configured for local PostgreSQL
- Initial schema baseline
- Safe migration of existing database
- Reproducible installation on an empty database
- No deletion of existing products or orders

### Offers
- Create offer for an existing product
- List offers by product
- Store price, currency and checkout URL
- Activate or deactivate offers
- Validate prices and checkout URLs
- Require administrative authorization for writes

### Product Lifecycle
- draft
- prepared
- approved
- live
- paused
- archived

Transitions must be explicitly validated.

Products cannot be published without
an approved offer and a valid checkout.

### Reliability
- Atomic database transactions
- Transactional outbox events
- Meaningful HTTP errors
- Integration tests
- Updated OpenAPI documentation

### Security
- Administrative authorization for writes
- Public queries expose only published products
- No payment credentials in source code

## Acceptance Criteria

1. Existing data survives migration.
2. Empty databases can be initialized.
3. Offers can be created and retrieved.
4. Duplicate or invalid operations are rejected.
5. Product transitions respect business rules.
6. State changes generate outbox events.
7. Automated tests pass.
8. OpenAPI and architecture docs are updated.
