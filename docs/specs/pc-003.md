# PC-003 — Landing Page Engine

Status: IN DEVELOPMENT

## Architecture

PostgreSQL remains the commercial source of truth.

The Python catalog exporter reads product and
offer data and generates static JSON snapshots.

Astro uses these snapshots to generate landing
pages at build time.

## Public Catalog

Source: catalog.public.json

Only products with status live and at least one
active offer with HTTPS checkout are exported.

## Preview Catalog

Source: catalog.preview.json

The preview catalog is local and ignored by Git.

Preview pages are available in development mode
only and must never be generated in production.

## Security

- Never expose ADMIN_API_KEY to browser code.
- Never query administrative API endpoints in the browser.
- Never publish draft products.
- Never enable a checkout button in preview mode.
- Static publication requires a build and deployment.
- Pausing a product requires removing its deployed page.

## Current Limitations

- Product marketing copy is not modeled yet.
- Checkout is not independently verified.
- Publication is not automated.
- No real sales analytics yet.
- The storefront has not been publicly deployed.

## PC-003.2 — Structured Commercial Content

Status: IN DEVELOPMENT

Database revision: 0003_product_page_content

### Data Model

Each product may have one commercial page.

Fields:
- headline
- subheadline
- description
- benefits (JSONB)
- faqs (JSONB)
- cta_label
- seo_title
- seo_description
- approved
- approved_at
- created_at
- updated_at

### Approval Rules

- New content starts unapproved.
- Editing content invalidates previous approval.
- Only an authenticated administrator can approve content.
- Approval is required before commercial publication.
- Archived products cannot receive content changes.
- Editing published content requires pausing the product.

### Security

Draft content must not enter the public catalog.

The exporter must refuse publication when a
live product lacks approved commercial content.

## PC-003.2C — Structured Content Rendering

Status: VALIDATED LOCALLY

### Catalog Contract

The public catalog contains:
- Product slug, name, audience and live status
- Approved commercial page content
- Active validated offers

Commercial page data contains:
- headline
- subheadline
- description
- benefits
- faqs
- cta_label
- seo_title
- seo_description

### Export Rules

- Draft products are never added to the public catalog.
- Live products require approved content.
- Live products require an active valid offer.
- Validation occurs before writing output.
- JSON snapshots are written atomically.

### Astro

The LandingPage component renders:
- Structured headlines
- Product description
- Benefits
- FAQ sections
- CTA and price
- SEO title and description
- Open Graph metadata

Preview mode disables purchasing and indexing.

### Build Pipeline

The npm prebuild script refreshes the catalog
from PostgreSQL before static page generation.

Publishing and unpublishing require rebuilding
and redeploying the static site.

The local build is not yet a production
deployment or immediate revocation mechanism.

### Limitations

- No real product marketing content has been entered yet.
- Checkout functionality is not independently verified.
- No production CDN deployment is configured.
- No payment or fulfillment automation is active.

## PC-003.2D — Product Visual Demonstrations

Status: VALIDATED LOCALLY

### Architecture

- Visual assets are stored in `apps/web/public/images/{slug}/`.
- Declarative metadata is maintained in `apps/web/src/data/product_media.json`.
- `scripts/export_catalog.py` attaches optional `media` payloads per slug without modifying database state or invalidating commercial content approval.
- `LandingPage.astro` conditionally renders real product screenshots with horizontal scroll containment on mobile and a native `<dialog>` lightbox for full-resolution inspection.
