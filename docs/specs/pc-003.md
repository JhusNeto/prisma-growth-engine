# PC-003 — Landing Page Engine

Status: IN DEVELOPMENT

## Architecture

PostgreSQL remains the commercial source of truth.

The Python catalog exporter reads product and
offer data and generates static JSON snapshots.

Astro uses these snapshots to generate landing
pages at build time.

## Public Catalog

Source: catalog.public.json

Only products with status live and at least one
active offer with HTTPS checkout are exported.

## Preview Catalog

Source: catalog.preview.json

The preview catalog is local and ignored by Git.

Preview pages are available in development mode
only and must never be generated in production.

## Security

- Never expose ADMIN_API_KEY to browser code.
- Never query administrative API endpoints in the browser.
- Never publish draft products.
- Never enable a checkout button in preview mode.
- Static publication requires a build and deployment.
- Pausing a product requires removing its deployed page.

## Current Limitations

- Product marketing copy is not modeled yet.
- Checkout is not independently verified.
- Publication is not automated.
- No real sales analytics yet.
- The storefront has not been publicly deployed.

## PC-003.2 — Structured Commercial Content

Status: IN DEVELOPMENT

Database revision: 0003_product_page_content

### Data Model

Each product may have one commercial page.

Fields:
- headline
- subheadline
- description
- benefits (JSONB)
- faqs (JSONB)
- cta_label
- seo_title
- seo_description
- approved
- approved_at
- created_at
- updated_at

### Approval Rules

- New content starts unapproved.
- Editing content invalidates previous approval.
- Only an authenticated administrator can approve content.
- Approval is required before commercial publication.
- Archived products cannot receive content changes.
- Editing published content requires pausing the product.

### Security

Draft content must not enter the public catalog.

The exporter must refuse publication when a
live product lacks approved commercial content.
